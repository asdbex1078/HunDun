# 动态链接与 GOT/PLT

## 描述

共享库在运行时才确定加载地址，调用它里面的函数、访问它里面的变量，都要等加载后才知道地址。动态链接器（`/lib64/ld-linux-x86-64.so.2`，本身也是 ELF 共享对象）在 [[ELF加载过程]] 的最后阶段接手：解析 `.dynamic`、加载 `DT_NEEDED` 依赖、执行[[重定位]]、解析符号、跑初始化函数、跳进 `main`。

靠的是 [[ELF节]] 里这一组节：`.interp`、`.dynamic`、`.dynsym`、`.dynstr`、`.gnu.hash`、`.rela.dyn`、`.rela.plt`、`.got`/`.got.plt`、`.plt`。

## 核心内容

### GOT/PLT 调用过程

外部函数调用通常被编译成：

```asm
call func@plt
```

PLT 桩跳转到 GOT 中存的地址。首次调用时，GOT 条目可能指向 PLT 里的解析代码，由动态链接器解析出真实地址并写回 GOT；之后再调用就直接跳过去。

这就是**延迟绑定**（lazy binding）。可以用 `LD_BIND_NOW=1` 或链接选项 `-z now` 改成立即绑定。

### 符号版本

glibc 使用符号版本，比如：

```text
memcpy@GLIBC_2.14
```

同一个库可以导出同一符号的多个版本，保证旧程序照样能跑。相关节：`.gnu.version`、`.gnu.version_d`、`.gnu.version_r`。这和 SONAME、动态标签一起，是 Linux 长期二进制兼容（ABI 稳定性）的基础。

### 性能与 ABI（作者从数据库角度的总结）

- **PLT/GOT 开销**：外部函数调用多一次跳转。可用 `-fno-plt`、`-Bsymbolic`、`-fvisibility=hidden` 优化
- **延迟绑定**：首次调用较慢；`-z now` 行为可预测但启动稍慢
- **静态 vs 动态链接**：数据库核心常动态链接 libc、libssl、libaio、libnuma
- **符号冲突**：多个插件可能导出同名符号，需要隐藏内部符号
- **LD_PRELOAD**：可以 hook、审计、测试（CSAPP 里叫库打桩），生产上要谨慎

### 个人理解

「内核只负责加载解释器，复杂符号解析放在用户态」是一个很干净的分工：内核的 ELF 加载器保持简单，动态链接策略（延迟绑定、版本、预加载）全部可以在用户态演进。
